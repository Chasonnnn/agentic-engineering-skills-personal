# Behavioral evaluation

Choose cases from the skill's real tasks and consequential uncertainties. Useful cases include intended selection, a nearby non-trigger, normal completion, and a relevant failure or permission boundary. Specify observable outcomes before changing the candidate. Do not require every case for every small edit.

Compare original and candidate using the same source snapshot, task prompt, runtime/model settings, tool access, and resource bounds. Freeze the skill versions and retain their hashes and raw outputs. Vary only the guidance under comparison where practical. Record departures, including extra reference-reading time.

For authorized independent evaluation, use fresh context and provide only the assigned method, task, and raw inputs. Withhold prior findings, expected answers, and other conditions' reports. Otherwise label scenario inspection as static reasoning. A target whose findings informed the revision is a regression case, not a new held-out test.

Assess actual artifacts and actions: supported findings, missed mechanisms, false positives, preserved useful guidance, completed work, extra work, unsupported success, and unnecessary interruptions. Match findings by cause rather than numbering; one auditor may split what another bundles. Adjudicate against source and relevant evidence, including counterevidence. Agreement among agents is not ground truth.

Measure time and usage before claiming efficiency. Name evaluator knowledge of condition labels, tooling differences, and checks not performed. One run per condition supports a bounded observation, not average improvement or general superiority.

Revise for demonstrated gaps. If a well-scoped direct prompt performs similarly, keep additional scaffolding optional instead of expanding it to absorb every finding. A successful regression check does not establish improved performance on unfamiliar skills.
